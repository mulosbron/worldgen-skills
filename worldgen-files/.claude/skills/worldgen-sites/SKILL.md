# Sites & Structures

Read `worldgen/architecture.md` (site types, persistence) and `worldgen/noise-results.md` (hash/seeds). KEY INSIGHT: organic systems (plants, terrain) WANT randomness — sites need GUARANTEES noise can't give ("a town spawns alone, with minimum distance to the next town", "every house connects to a path"). Use structured randomness: grid + hash, not raw noise.

## System 1 — WHERE: Jittered grid sampling (placement with guarantees)
1. Slice the world into **sectors** (each sector = a set of chunks, e.g. 8×8 chunks).
2. When the first chunk of a sector loads: derive the sector seed `pos_seed(master, sector_x, sector_y, "town")`.
3. From that seed, pick ONE jittered position inside the sector → attempt to generate the site there.
4. **Dead zone**: forbid placement within the sector's border margin → every site is guaranteed a minimum distance from every other site, in all scenarios, with zero global coordination.
5. Pipeline: position → bounds/validity check (not in water, not on cliff — sample the terrain/biome data) → generate the site's data → keep in memory → load into the world when the player gets close. Fully deterministic from the master seed.
Generalizes to ANY site type needing spacing: towns, ruins, boss arenas, quest markers. One sector grid per site type (different sizes per type).

## System 2 — WHAT: Wave Function Collapse (rule-following layouts)
WFC fills a grid of cells, each cell constrained by rules to allowed contents; cells start in **superposition** (all possible states) and collapse one by one until the grid is a valid layout.
**Frontier-based collapse** (simple, robust variant):
```gdscript
# RULES example: town cells = CENTER, HOUSE, PATH, PLAZA, EMPTY
# adjacency: HOUSE must neighbor PATH; PATH must connect toward CENTER; CENTER exactly 1
1. collapse(center_cell, "CENTER")
2. frontier = orthogonal neighbors of center; update their possible states from rules
3. while frontier not empty:
       c = pick frontier cell (lowest entropy = fewest possible states, ties random by seed)
       collapse(c, weighted_random_choice(c.possible_states))
       add c's orthogonal neighbors to frontier; update their states
4. done — every cell collapsed consistently
```
- Seeded randomness per cell → the SAME town regenerates identically from the same seed, but different seeds give different towns.
- The ruleset is where design lives: houses need path adjacency; paths need a connection direction; plazas appear near center. Start with 4–6 cell types.
- Same machinery generates dungeons, ruins, anything grid-layoutable.

## System 3 — Dungeons by room stitching (Binding-of-Isaac pattern)
For hand-authored-feel dungeons instead of WFC:
1. Start with a default start room.
2. Loop: pick a random side of a random existing room → place a random room from the **predefined layout library** on that side (skip if occupied).
3. Stop at target room count → place the boss room far from start → optionally a treasure room.
4. Populate rooms with chests/enemies from per-room tables.
Random GENERATION from authored CONTENT: the game decides where/how, artists decide what. Rooms are whole-unit nodes — no tile-level rules needed.

## System 4 — Critical structure placement (stronghold pattern)
Game-completion-critical locations get geometric guarantees, not probabilities:
- N total structures in R concentric rings; ring k has radius range [r_min, r_max] and holds its share of structures at roughly **equal angles**.
- Positions are computed BEFORE terrain/features (they're that important), then terrain generates around them.
- Apply to: final dungeons, quest hubs, fast-travel anchors.

## System 5 — Interiors as world-spaces
Any site with an interior (houses, inns, shops, cave-like ruins) should load its interior as a separate scene/world-space keyed by an ID — the same mechanism caves use. Doors are just transitions: interact → load `site_id` interior. Keeps the outdoor isometric/top-down view clean and makes interiors free-form.

## Determinism & persistence
- Site data is a pure function of (master seed, sector coords). With delta persistence, store only player edits inside sites (opened chests, broken walls) keyed by `site_id + cell`.
- Sites that fail validity checks (bad terrain) simply don't spawn this seed — that's correct behavior, not a bug. Log them during development.

## Output format
Write to `worldgen/sites-results.md`: per-site-type decisions (placement system + layout system), sector size / dead zone / ring parameters, the actual ruleset for WFC or room library structure, code as written, memory-loading flow, verification (distance histogram between sites; rendered sample towns/dungeons), tuning notes.

## Pitfalls
- Using noise thresholds for town placement → occasional overlapping towns, impossible to guarantee spacing. Jittered grid exists exactly for this.
- WFC without lowest-entropy selection → frequent contradictions/dead ends. Pick the most-constrained cell each step.
- Forgetting bounds/terrain validity checks → towns floating in oceans.
- Generating site interiors into the outdoor map → visual chaos; use world-spaces.
